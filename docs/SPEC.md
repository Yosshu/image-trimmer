# image-trimmer 仕様書（Windows フォト「トリミング」再現）

Windows 11 の「フォト」アプリ → 画像の編集 → **トリミング** ツールを、UI・挙動ともに Web 上で再現し、GitHub Pages で公開する。

- 再現対象：ユーザー提供スクリーンショットのバージョン（2026年10月時点の安定版）
- 範囲外：調整・フィルター・マークアップ・消去・背景などトリミング以外の編集ツール。**アイコンも置かない**（トリミングのアイコン1つだけ残すこともしない）
- 画像はブラウザ内だけで処理し、外部へ送信しない
- 参考スクリーンショットはリポジトリに入れない（手元の任意の画像で撮ったもののため）

> 凡例：**【確定】** スクショ／ユーザー回答で確認済み、**【案】** Web 版としての方針（ユーザー確認中）、**【未確定】** 要確認（§8 に一覧）、**【Web独自】** 本家にない Web 版だけの要素

## 1. 画面構成

### 1.1 全体
- 背景色（ダーク）：`#202020` 【確定】
- 画像の描画領域は、上部ツールバーの下端からウィンドウ下端まで【確定】
  - 上端はツールバーの下端で**水平に切り取られる**（大きく拡大・回転した画像もツールバーには重ならない）
  - 下部の角度スライダーやボタン列は、画像の**上に重なって**表示される（画像はスライダーの裏まで見える）
- トリミング枠は、ツールバーとスライダーに挟まれた領域の中央に、縦横比を保ったまま最大サイズでフィットさせる 【確定】
  - 実測：ウィンドウ 1902×970 のとき、枠の最大の高さは約 602px（y=172〜774）

### 1.2 上部ツールバー 【確定】
| 位置 | 要素 | 備考 |
|---|---|---|
| 左グループ | ズームイン 🔍+ / ズームアウト 🔍− / 実際のサイズ（1:1） / ズーム率「83%」 / 縦の区切り線 / 「リセット」 / 元に戻す ↶ / やり直し ↷ | 角丸のボックスでまとめる（背景 `#1F1F1F`、ページ背景との差はわずか） |
| 中央 | **何も置かない** | |
| 右 | 「保存オプション ∨」（アクセントカラーのボタン）、「キャンセル」 | 中身は §1.3 |

- 有効なアイコンは `#FFFFFF`、無効なアイコンは約 `#797979`
- 無効になる条件：
  - リセット・元に戻す・やり直し：その操作ができないとき（初期状態など）
  - ズームアウト：これ以上縮小すると枠が画像からはみ出すとき（枠が画像いっぱいのとき）
  - 実際のサイズ（1:1）：トリミング中は観測した限り常に無効
- ボタンにカーソルを置くと、角丸の背景 `#3B3A39` でハイライトする
- 実測（スクショ上の px）：
  - 左グループ：高さ約 53、ズーム系アイコンの間隔 50、元に戻す・やり直しの間隔 48
  - 保存オプション：198×39、キャンセル：137×39、2つの間隔 11、右余白 約 24

### 1.3 右上（保存オプション / キャンセル）
**本家の構成** 【確定】
- 「保存オプション ∨」の直下に、ボタンの左端に揃えてメニューを表示する
- 項目（上から）：**コピーとして保存** / **保存** / **クリップボードにコピー**
  - 本家では「保存」＝元ファイルへの上書き、「コピーとして保存」＝名前を付けて保存（保存先・ファイル名・形式を選ぶダイアログが出る）
  - 「保存」はグレーで無効になる場合がある
- メニュー：背景 `#2C2C2C`、文字 `#FFFFFF`、無効時の文字は約 `#777777`
- 「キャンセル」で編集を終える。編集した後だと確認のポップアップが出る

**Web 版での扱い** 【案】
- ユーザーの要望：右上で使えるのは「**名前を付けて保存**」と「**クリップボードにコピー**」の2つ
- 案：「保存オプション ∨」の見た目はそのままにし、メニューを「コピーとして保存」「クリップボードにコピー」の2項目にする（上書きの「保存」は外す）
- 「キャンセル」の扱いは確認中（§8）

### 1.4 トリミング枠 【確定】
- 細い白の枠線、四隅に太い L 字ハンドル、各辺の中央に短いバーのハンドル
- 枠の外側の画像は暗いオーバーレイで覆う
- **ドラッグ中**：
  - 枠内に三分割のグリッド線（縦2本・横2本、1px の半透明の白い破線）を表示する
  - 枠内の下中央に、サイズを示す半透明の暗いラベル「395 x 666」を表示する
- **手を離すと**グリッドが消え、枠が画面中央に戻って、フィットするまで拡大される（ズーム率も変わる）
- **比率ピッカーを開いている間**：
  - 枠内の下中央にサイズ「422 x 316」を表示する
  - 固定比率を選んでいるときは、上中央に比率「4 : 3」も表示する（「自由」のときは出さない）
- サイズの数値は**元画像のピクセル数**で表す（画面上の px ではない）

### 1.5 角度スライダー（傾き補正） 【確定】
- 範囲：**−45° 〜 +45°**（90° 回転と組み合わせれば、どの角度にもできるため広げない）
- 正の値＝時計回り
- 値のラベルはつまみの真上。小数第1位まで表示する（例「12.4 °」）。整数ちょうどのときは「0 °」「-45 °」のように表示する
- ルーラー型：
  - **つまみは中央に固定**で、目盛りのテープのほうが左右に流れる
  - 1° ごとに小さなドット、5° ごとに長い目盛り（幅約3px・高さ約14px）
  - 間隔は約 15.2px / 1°
  - 表示するのは現在値の ±約28°（約 850px 幅）。両端はフェードアウトさせる
  - −45° より左、+45° より右には何も描かない（−45° のとき、つまみの左側は空になる）
  - 0° の位置には、つまみと重なっていなければ目盛りの代わりに数字「0」を表示する
- つまみ：白い縦長のピル形、約 10×28px

### 1.6 下部のボタン列 【確定】
- 横幅はルーラーと同じ（約 850px）で、左寄せ・中央・右寄せの3グループに分ける
- 左：反時計回りに 90° 回転 ↺、時計回りに 90° 回転 ↻（間隔約 52）
- 中央：［現在の比率のアイコン］＋現在の比率名（例「自由」「9 : 16」）。押すと比率ピッカーが開く
- 右：左右反転 ⇄、上下反転 ⇅（間隔約 53）
- 配置：ルーラーの約 60px 下

### 1.7 比率ピッカー 【確定】
- 角度スライダーと下部ボタン列の**代わりに**表示する
- 15項目を横一列に約 100px 間隔で並べる。各項目は「アイコン＋ラベル」
- アイコンは、その比率の形をした角丸の四角（自由とオリジナルは専用アイコン）
- 選択中の項目：アイコンの背景を角丸（約 60×60）でハイライトし、ラベルを太字にする
- 一覧の下中央に「完了」

| ラベル | 比率 | ツールチップ |
|---|---|---|
| 自由 | 制約なし | 自由な縦横比 |
| オリジナル | 元画像の比率 | 元の縦横比 |
| 正方形 | 1:1 | 正方形の縦横比 |
| 9 : 16 | 9:16 | 9 x 16 の縦横比（推定） |
| 16 : 9 | 16:9 | 16 x 9 の縦横比 |
| 4 : 5 / 5 : 4 / 3 : 4 / 4 : 3 / 2 : 3 / 3 : 2 / 5 : 7 / 7 : 5 / 1 : 2 / 2 : 1 | 同左 | 「W x H の縦横比」の形（推定） |

### 1.8 ツールチップ 【確定】
スタイルは2種類ある。
- **A（ボタン・スライダー・枠）**：背景 `#292929`、**2px の白い枠線**、角は丸めない、白い文字。対象の右下あたりに表示する
- **B（保存オプションのメニュー項目）**：角丸、白い枠線なし、背景は暗いグレー、文字はやや太め。幅に収まらない文言は折り返す。メニューの左側に表示する

| 対象 | 文言 | スタイル |
|---|---|---|
| 反時計回りに回転 | 画像を反時計回りに 90 度回転 | A |
| 時計回りに回転 | 画像を時計回りに 90 度回転 | A |
| 左右反転 | 画像を水平方向に反転 | A |
| 上下反転 | 画像を垂直方向に反転 | A |
| 角度スライダー | ドラッグするか、方向キーを使用して画像を回転 | A |
| トリミング枠（枠の上にカーソルを置いたとき） | ハンドルをドラッグするか、矢印キーを使用して画像をトリミングします | A |
| 元に戻す | 元に戻す | A |
| 比率ピッカーの各項目 | 1.7 の表を参照 | A |
| メニュー「クリップボードにコピー」 | 画像をクリップボードにコピーします | B |
| その他（ズームイン、ズームアウト、実際のサイズ、リセット、やり直し、比率ボタン、保存オプション、キャンセル、メニュー「コピーとして保存」） | 【未確定】ユーザーから順次受け取る | |

## 2. 挙動

### 2.1 角度補正
- 枠の画面上のサイズは変えずに、回転した画像が枠を完全に覆うよう、画像を自動で拡大する（83% → 112% のようにズーム率が上がる）【確定】
- 回転後の画像の外側（余白）が枠内に入ることは決してない
- スライダーは方向キーでも操作できる（ツールチップより）【確定】。1回押したときの変化量は【未確定】

### 2.2 90° 回転・反転
- 90° 回転は ↺ / ↻ の1クリックで ±90°
- **枠も画像と一緒に回転する**【確定】
  - 例：16:9 で 422×237 の枠のまま ↻ を押すと、比率は 9:16、枠は 237×422 になる
  - 下部の比率ボタンと枠上の比率ラベルも「9 : 16」に変わる
  - 回転後の画像と枠は、改めて画面にフィットさせる
- 左右反転・上下反転：枠が画像に対して反転するかは【未確定】（見た目の位置を保つ想定）

### 2.3 枠のドラッグ
- 四隅：2辺を同時に動かす。各辺の中央：その1辺だけ動かす
- 固定比率のときは比率を保って変形する
- 枠は回転後の画像の内側に制限する
- ドラッグ中はグリッドとサイズを表示し、離すと中央に戻して拡大する（アニメーションあり）【確定】
- **枠の内側（ハンドル以外）をドラッグすると、枠は動かず、後ろの画像がスライドする**【確定】
  - 画像の外側が枠内に入らないよう制限する
- 枠は矢印キーでも操作できる（ツールチップより）【確定】。どのキーで何が動くかは【未確定】（Windows 10 版フォトでは Shift+矢印でサイズ変更、Ctrl+矢印で移動だった）

### 2.4 比率の選択
- 比率を選ぶと、枠をその比率に変えて画面にフィットさせる（ズーム率が変わる）【確定】
- 画像を開いた直後（枠＝画像全体）に選んだ場合は、**画像に収まる最大サイズを中央に置く**【確定】
  - 例：422×717 の画像で 16:9 → 422×237、4:3 → 422×316
- 枠を一度変えたあとに比率を選んだ場合【未確定】。今の枠の中心は保つと考えられるが、大きさの決め方は次のどちらか：
  - 仮説 A：今の枠の内側に収まる最大サイズ
  - 仮説 B：今の枠の中心を保ったまま、画像に収まる最大サイズ
  - どちらでも、観測した「296×666 の枠から 9:16 → 296×527」と一致する

### 2.5 ズーム
- **ズームしても枠の画面上のサイズは変わらず、後ろの画像だけが拡大・縮小する**【確定】
  - そのため、拡大すると切り抜かれる範囲（元画像のピクセル数）が小さくなる。例：83% で 422×717 の枠が、166% では 212×361 になる
  - 縮小は、枠が画像からはみ出さないところまで。限界ではズームアウトのボタンが無効になる
- ズーム率は「元画像の 1px が画面上の何 px に表示されているか」を表す（例：83%）
  - Web 版では `devicePixelRatio` を掛けて、物理ピクセルを基準に計算する
- マウスホイールの動作は【未確定】

### 2.6 リセット / 元に戻す / やり直し
- リセット：すべての編集を初期状態に戻す
- 元に戻す：Ctrl+Z、やり直し：Ctrl+Y（Windows フォトの従来のショートカット）
- 履歴の単位は、ドラッグ1回・ボタン1回・スライダー操作1回

### 2.7 保存 / キャンセル
- 書き出しは**元画像の解像度**で行い、回転・反転・切り抜きを適用する
- **コピーとして保存（名前を付けて保存）** 【案】
  - 本家：保存先・ファイル名（元のファイル名が入っている）・形式を選ぶダイアログが出る。形式は PNG / JPEG / TIFF / BMP / JPEG XR / HEIC【確定】
  - Web 版（Chrome / Edge）：`showSaveFilePicker` で OS の「名前を付けて保存」ダイアログを出す。ファイル名は元の名前、形式の一覧も指定する
  - Web 版（Firefox / Safari など。このダイアログが使えないブラウザ）：ファイル名と形式を選ぶ小さなダイアログを Fluent の見た目で出し、ダウンロードとして保存する【Web独自】
  - 形式は **PNG / JPEG / TIFF / BMP**。ブラウザの機能で出力できない TIFF と BMP は、小さなエンコーダーを自作する。JPEG XR と HEIC はブラウザでは出力できないので外す
  - 初期の形式は元画像と同じ（対応外の形式なら PNG）
- **クリップボードにコピー**：Clipboard API で PNG としてコピーする 【案・ユーザー要望】
- **キャンセル**：編集を破棄して開始画面に戻る。確認ポップアップを出すかは【未確定】

## 3. Web 版独自の要素 【Web独自】
- **開始画面**：「画像を開く」ボタン（ファイル選択）、ドラッグ＆ドロップ、Ctrl+V での貼り付けに対応する。見た目は Fluent デザインに合わせる

## 5. 技術構成（予定）
- Vite + TypeScript。UI フレームワークは使わない
- 画像の表示と書き出しは Canvas 2D
- 状態は、回転角・90° 回転回数・反転・元画像座標系での枠・比率・ズームで持つ。Undo / Redo はこの状態のスナップショットで管理する
- デプロイ：GitHub Actions → GitHub Pages（リポジトリの Settings → Pages → Source を「GitHub Actions」にする必要がある）

---

## 6. 実装上の要点（難所）
1. **回転時の自動拡大**：回転した矩形（画像）が、軸に平行な矩形（枠）を含むために必要な最小の拡大率を求める
2. **枠の制約**：ドラッグ中の枠や、スライドさせた画像が、回転後の画像の外にはみ出さないよう制限する（比率固定の場合も含む）
3. **フィットのアニメーション**：手を離したあと、枠を中央に戻して拡大する遷移をなめらかにする
4. **ルーラー型スライダー**：つまみを固定し、テープのほうを流す。両端はフェードさせる
5. **書き出し**：元の解像度で、回転・反転・切り抜きを正確に適用する。TIFF と BMP のエンコーダーを用意する

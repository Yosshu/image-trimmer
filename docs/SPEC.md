# image-trimmer 仕様書（Windows フォト「トリミング」再現）

Windows 11 の「フォト」アプリ → 画像の編集 → **トリミング** ツールを、UI・挙動ともに Web 上で再現し、GitHub Pages で公開する。

- 再現対象：ユーザー提供スクリーンショットのバージョン（2026年10月時点の安定版）
- 範囲外：調整・フィルター・マークアップ・消去・背景などトリミング以外の編集ツール。**アイコンも置かない**（トリミングのアイコン1つだけ残すこともしない）
- 画像はブラウザ内だけで処理し、外部へ送信しない
- 参考スクリーンショットはリポジトリに入れない。写っている画像の内容も書かない

> 凡例：**【確定】** スクショ／ユーザー回答で確認済み、**【決定】** Web 版としてユーザーと合意した方針、**【既定】** 本家で未確認のため、こちらで決めた挙動（後から変更可）、**【Web独自】** 本家にない Web 版だけの要素

## 0. 寸法の単位
- スクショは Windows の表示スケール **125%** で撮られている【確定】
- 本書の寸法は特に断りがなければ **CSS px**（スクショの px ÷ 1.25）で書く
- 基準のウィンドウは 1902×970 物理px ＝ **1522×776 CSS px**

## 1. 画面構成

### 1.1 全体
- 背景色：ダーク `#202020`【確定】／ライト §4 参照
- 上部ツールバーの領域：高さ約 74
- 画像の描画領域は、ツールバーの下端からウィンドウ下端まで【確定】
  - 上端はツールバーの下端で**水平に切り取られる**（大きく拡大・回転した画像もツールバーには重ならない）
  - 下部の角度スライダー・ボタン列・比率ピッカーは、画像の**上に重なって**表示される（画像はそれらの裏まで見える）
- トリミング枠は、次の領域の中央に、縦横比を保ったまま最大サイズでフィットさせる【確定】
  - 基準のウィンドウで y=138〜619（高さ約 482）。上はツールバーから約 64 空け、下はウィンドウ下端から約 157 空ける
  - 左右の余白は【既定】として最低 64
- 画面が狭い場合（スマホなど）【Web独自】：
  - 余白とルーラーの幅を縮める
  - 比率ピッカーは横にスクロールできるようにする
  - マウスに加えてタッチ操作にも対応する（Pointer Events）

### 1.2 上部ツールバー 【確定】
| 位置 | 要素 | 備考 |
|---|---|---|
| 左グループ | ズームイン 🔍+ / ズームアウト 🔍− / 実際のサイズ（1:1） / ズーム率「83%」 / 縦の区切り線 / 「リセット」 / 元に戻す ↶ / やり直し ↷ | 角丸のボックスでまとめる（ダークの背景 `#1F1F1F`、ページ背景との差はわずか） |
| 中央 | **何も置かない** | |
| 右 | 「保存オプション ∨」（アクセントカラーのボタン）、「キャンセル」 | 中身は §1.3 |

- 寸法：
  - 左グループ：高さ約 42、ズーム系アイコンの間隔 40、元に戻す・やり直しの間隔 38
  - アイコンは 16、文字は 14
  - 保存オプション：約 158×32、キャンセル：約 110×32、2つの間隔 約 8、右余白 約 20
- 有効なアイコンは文字色、無効なアイコンは薄い灰色（ダーク：約 `#797979`）
- 無効になる条件：
  - リセット・元に戻す・やり直し：その操作ができないとき（初期状態など）
  - ズームアウト：これ以上縮小すると枠が画像からはみ出すとき
  - 実際のサイズ（1:1）：トリミング中は観測した限り常に無効
- ボタンにカーソルを置くと、角丸の背景でハイライトする（ダーク `#3B3A39`）

### 1.3 右上（保存オプション / キャンセル） 【決定】
- 「保存オプション ∨」：アクセントカラーのボタン。見た目は本家のまま
- 押すと、直下にボタンの左端に揃えてメニューを出す。項目は2つ：
  1. **コピーとして保存**（名前を付けて保存。§2.7）
  2. **クリップボードにコピー**
- 本家の「保存」（元ファイルへの上書き）は Web 版では置かない
- メニュー：ダークの背景 `#2C2C2C`、文字 `#FFFFFF`
- **キャンセル**：残す。編集を破棄して開始画面に戻る（§2.7）

### 1.4 トリミング枠 【確定】
- 細い白の枠線、四隅に太い L 字ハンドル、各辺の中央に短いバーのハンドル
- 枠の外側の画像には、背景色を約 75% の不透明度で重ねる（実測：ダークでは白が約 `#595959` に見える）
- **ドラッグ中**：
  - 枠内に三分割のグリッド線（縦2本・横2本、1px の半透明の白い破線）を表示する
  - 枠内の下中央に、サイズを示す半透明の暗いラベル「395 x 666」を表示する
- **手を離すと**グリッドが消え、枠が画面中央に戻って、フィットするまで拡大される（ズーム率も変わる）
- **比率ピッカーを開いている間**：
  - 枠内の下中央にサイズ「422 x 316」を表示する
  - 固定比率を選んでいるときは、上中央に比率「4 : 3」も表示する（「自由」のときは出さない）
- サイズの数値は**元画像のピクセル数**で表す

### 1.5 角度スライダー（傾き補正） 【確定】
- 範囲：**−45° 〜 +45°**（90° 回転と組み合わせれば、どの角度にもできるため広げない）
- 正の値＝時計回り
- 値のラベルは、つまみの真上（ルーラーの約 34 上）。小数第1位まで表示する（例「12.4 °」）。整数ちょうどのときは「0 °」「-45 °」のように表示する
- ルーラー型：
  - **つまみは中央に固定**で、目盛りのテープのほうが左右に流れる
  - 1° ごとに小さなドット（約 2）、5° ごとに長い目盛り（約 2×11）
  - 間隔は約 **12.2 / 1°**
  - 表示するのは現在値の ±約28°（幅約 680）。両端はフェードアウトさせる
  - −45° より左、+45° より右には何も描かない（−45° のとき、つまみの左側は空になる）
  - 0° の位置には、つまみと重なっていなければ目盛りの代わりに数字「0」を表示する
- つまみ：縦長のピル形、約 8×22（ダークでは白）
- 配置：ルーラーの中心は、基準のウィンドウで y≈700

### 1.6 下部のボタン列 【確定】
- ルーラーの約 48 下に置く。横幅はルーラーと同じ（約 680）で、左寄せ・中央・右寄せの3グループに分ける
- 左：反時計回りに 90° 回転 ↺、時計回りに 90° 回転 ↻（間隔約 42）
- 中央：［現在の比率のアイコン］＋現在の比率名（例「自由」「9 : 16」）。押すと比率ピッカーが開く
- 右：左右反転 ⇄、上下反転 ⇅（間隔約 42）

### 1.7 比率ピッカー 【確定】
- 角度スライダーと下部ボタン列の**代わりに**表示する
- 15項目を横一列に約 80 間隔で並べる。各項目は「アイコン＋ラベル」（アイコンの中心からラベルの中心まで約 39）
- アイコンは、その比率の形をした角丸の四角（自由とオリジナルは専用アイコン）
- 選択中の項目：アイコンの背景を角丸（約 48×48）でハイライトし、ラベルを太字にする
- 一覧の下中央、ラベルの約 40 下に「完了」

| ラベル | 比率 | ツールチップ |
|---|---|---|
| 自由 | 制約なし | 自由な縦横比 |
| オリジナル | 元画像の比率 | 元の縦横比 |
| 正方形 | 1:1 | 正方形の縦横比 |
| 9 : 16 | 9:16 | 9 x 16 の縦横比 |
| 16 : 9 | 16:9 | 16 x 9 の縦横比 |
| 4 : 5 / 5 : 4 / 3 : 4 / 4 : 3 / 2 : 3 / 3 : 2 / 5 : 7 / 7 : 5 / 1 : 2 / 2 : 1 | 同左 | 「W x H の縦横比」の形 |

## 2. 挙動

### 2.1 角度補正 【確定】
- 枠の画面上のサイズは変えずに、回転した画像が枠を完全に覆うよう、画像を自動で拡大する（83% → 112% のようにズーム率が上がる）
- 回転後の画像の外側（余白）が枠内に入ることは決してない
- スライダーは方向キーでも操作できる（ツールチップより）
  - 1回押したときの変化量は【既定】で 1°（Shift と一緒に押すと 0.1°）

### 2.2 90° 回転・反転
- 90° 回転は ↺ / ↻ の1クリックで ±90°
- **枠も画像と一緒に回転する**【確定】
  - 例：16:9 で 422×237 の枠のまま ↻ を押すと、比率は 9:16、枠は 237×422 になる
  - 下部の比率ボタンと枠上の比率ラベルも「9 : 16」に変わる
  - 回転後の画像と枠は、改めて画面にフィットさせる
- 左右反転・上下反転【既定】：
  - 枠の中心を軸に画像を反転する
  - 枠の位置と大きさは変わらず、枠内の画像が鏡写しになる
  - 画面の見た目全体がそのまま鏡写しになる。そのため、角度補正がかかっている場合はスライダーの値の符号が反転する

### 2.3 枠のドラッグ
- 四隅：2辺を同時に動かす。各辺の中央：その1辺だけ動かす
- 固定比率のときは比率を保って変形する
- 枠は回転後の画像の内側に制限する
- ドラッグ中はグリッドとサイズを表示し、離すと中央に戻して拡大する（アニメーションあり）【確定】
- **枠の内側（ハンドル以外）をドラッグすると、枠は動かず、後ろの画像がスライドする**【確定】
  - 画像の外側が枠内に入らないよう制限する
- 枠は矢印キーでも操作できる（ツールチップより）【確定】
  - キーの割り当ては【既定】で次のとおり：
    - Tab で枠にフォーカスする
    - 矢印キー：画像をスライドする
    - Shift＋矢印キー：右辺・下辺を動かして枠のサイズを変える（Windows 10 版フォトの操作に合わせる）
  - 動く量は 1 画面px、Ctrl と一緒に押すと 10 画面px

### 2.4 比率の選択 【確定】
- 比率を選ぶと、**今の枠の中心を保ったまま、回転後の画像に収まる最大サイズ**の枠にする
  - 中心からの距離で上下左右の余裕が違う場合は、中心を動かさずに小さいほうの余裕に合わせる
  - そのあと画面にフィットさせる（ズーム率が変わる）
- 実測例（422×717 の画像）：
  - 開いた直後に 9:16 → 403×717、続けて 16:9 → 422×237（今の枠の内側ではなく、画像の範囲で最大になる）
  - 開いた直後に 4:3 → 422×316
  - 右端に寄せた 296 幅の枠から 9:16 → 296×527（中心を保つので幅で制限される）
- 「オリジナル」は元画像の比率。90° 回転しているときは縦横を入れ替える
- 「自由」は今の枠をそのまま残し、比率の制約だけ外す

### 2.5 ズーム 【確定】
- **ズームしても枠の画面上のサイズは変わらず、後ろの画像だけが拡大・縮小する**
  - そのため、拡大すると切り抜かれる範囲（元画像のピクセル数）が小さくなる。例：83% で 422×717 の枠が、166% では 212×361 になる
  - 縮小は、枠が画像からはみ出さないところまで。限界ではズームアウトのボタンが無効になる
- ズーム率の **100% は、画像が実際のピクセル数で表示される大きさ**【決定】
  - 元画像の 1px を画面の物理ピクセル 1px で表示する状態。本家も同じで、125% の環境で 422px 幅の画像が 83% のとき、物理 約 350px で表示される
  - Web 版では `devicePixelRatio` を使って計算する
- ズームボタンの1回あたりの倍率と、拡大の上限は【既定】で、×1.25 刻み・上限 1600%
- マウスホイール【既定】：ズームイン／ズームアウトと同じ動作。カーソル位置ではなく枠の中心を基準にする

### 2.6 リセット / 元に戻す / やり直し
- リセット：すべての編集を初期状態に戻す
- 元に戻す：Ctrl+Z、やり直し：Ctrl+Y（Windows フォトの従来のショートカット）
- 履歴の単位は、ドラッグ1回・ボタン1回・スライダー操作1回（ドラッグの開始から終了まで）

### 2.7 保存 / キャンセル 【決定】
- 書き出しは**元画像の解像度**で行い、回転・反転・切り抜きを適用する
- **コピーとして保存（名前を付けて保存）**：
  - 本家では、保存先・ファイル名（元のファイル名が入っている）・形式を選ぶダイアログが出る。形式は PNG / JPEG / TIFF / BMP / JPEG XR / HEIC【確定】
  - Chrome / Edge：`showSaveFilePicker` で OS の「名前を付けて保存」ダイアログを出す。ファイル名は元の名前、形式の一覧も指定する
  - Firefox / Safari など（このダイアログが使えないブラウザ）：ファイル名と形式を選ぶ小さなダイアログを Fluent の見た目で出し、ダウンロードとして保存する【Web独自】
  - 形式は **PNG / JPEG / TIFF / BMP**。ブラウザの機能で出力できない TIFF と BMP は、小さなエンコーダーを自作する。JPEG XR と HEIC はブラウザでは出力できないので外す
  - 初期の形式は元画像と同じ（対応外の形式なら PNG）。JPEG の品質は【既定】で 0.95
- **クリップボードにコピー**：Clipboard API で PNG としてコピーする
- **キャンセル**：
  - 編集を破棄して開始画面に戻る
  - 確認ポップアップは出さない（本家は出すが、Web 版では不要と判断）

## 5. 技術構成（予定）
- Vite + TypeScript。UI フレームワークは使わない
- 画像の表示と書き出しは Canvas 2D
- 状態は、回転角・90° 回転回数・反転・元画像座標系での枠・比率・ズームで持つ。Undo / Redo はこの状態のスナップショットで管理する
- 回転・枠の制約・フィットなどの幾何計算は、純粋な関数として分けてユニットテスト（Vitest）を書く
- デプロイ：GitHub Actions → GitHub Pages
  - リポジトリの Settings → Pages → Source を「GitHub Actions」にする必要がある（ユーザー側の操作）

## 6. 実装上の要点（難所）
1. **回転時の自動拡大**：回転した矩形（画像）が、軸に平行な矩形（枠）を含むために必要な最小の拡大率を求める
2. **枠の制約**：ドラッグ中の枠や、スライドさせた画像が、回転後の画像の外にはみ出さないよう制限する（比率固定の場合も含む）
3. **比率の切り替え**：中心を保ったまま、回転後の画像に収まる最大の矩形を求める
4. **フィットのアニメーション**：手を離したあと、枠を中央に戻して拡大する遷移をなめらかにする
5. **ルーラー型スライダー**：つまみを固定し、テープのほうを流す。両端はフェードさせる
6. **書き出し**：元の解像度で、回転・反転・切り抜きを正確に適用する。TIFF と BMP のエンコーダーを用意する
